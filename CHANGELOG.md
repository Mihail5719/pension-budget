## [2.3.0] - 2026-11-17

### 🎉 Новые возможности
- **Прозрачная детализация расходов**: при просмотре категории в режиме «Обзор» фиксированные и обычные платежи теперь показываются раздельно. Сумма «Итого» считается честно, только по выбранной группе.
- **Мобильные подсказки**: долгое нажатие на подкатегорию или товар в режиме «Анализ» показывает его процент от родительской категории (независимо от капризов браузера).
- **Актуализация версии**: номер версии (2.3.0) теперь явно указан в интерфейсе (экран «О приложении») и в `manifest.json`.

### 📱 Улучшения UX/UI
- **Удобная навигация в «Анализе»**: категории теперь свёрнуты по умолчанию, чтобы не перегружать экран информацией.
- **Идеальное выравнивание**: суммы расходов на вкладке «Анализ» строго выровнены по правому краю, независимо от длины названия категории.
- **Актуальное описание**: полностью переработан и дополнен текст на экране «О приложении» с перечислением всех ключевых функций.

### 🐛 Исправления
- **Надёжный парсинг чисел**: ввод значений с пробелами и запятыми в настройках (например, `34 714,73`) больше не обрезается до `34` после перезагрузки страницы.
- **Честный расчёт лимита**: функция расчёта дневного лимита теперь использует реальный баланс (`currentBalance`), включающий процентные доходы. Это устраняет ложные отрицательные остатки при обнулении неприкосновенного запаса.
- **Чистота аналитики**: скрыты фантомные записи товаров без имени и с нулевой суммой в «Анализе» (артефакты миграции старых данных).

### 🔧 Технические изменения
- Актуализирована структура проекта в `README.md`: добавлены отсутствующие файлы и папки (`icons/`, `chart.min.js`, `user-guide.md`, `screenshots/`), убран дублирующий `docs/README.md` (переименован в `PROJECT-WIKI.md`).
- Уточнено описание локальных файлов: в `README.md` добавлено примечание, что папка `backup/` и файл `COMMENTS.md` хранятся только локально и игнорируются Git.

## [2.2.0] - 2026-11-09

### 🎉 Новые возможности
- **Поиск по истории**: мгновенная фильтрация записей по категории, предмету, месту или комментарию.
- **Архивация транзакций**: возможность скрыть отдельные записи или целые периоды без удаления, с функцией индивидуального и массового восстановления.
- **Гибкие фильтры по датам**: просмотр истории за день, неделю, месяц или любой произвольный период через встроенный календарь.
- **Фильтр по счетам**: изоляция операций конкретного банка или наличных в общем списке истории.
- **Drill-down в статистике**: клик по категории открывает детальный список конкретных транзакций за выбранный период с итоговой суммой.
- **Синхронизация периодов**: экран статистики автоматически подхватывает даты, выбранные в фильтре истории операций.

### 🐛 Исправления
- **Точный учёт доходов в произвольных периодах**: корректный расчёт пенсий/зарплат при просмотре длинных периодов (теперь сумма умножается на количество месяцев в выбранном диапазоне, а не добавляется однократно).
- **Умный перенос дат фиксированных платежей**: автоматическая корректировка с 29-31 числа на последний день месяца (например, на 28 февраля), чтобы обязательные платежи не "пропадали" из расчётов.

### 🔧 Технические изменения
- Реализован алгоритм подсчёта количества периодов пенсии через цикл по месяцам в функции `renderStats` (`ui.js`).
- Добавлена синхронизация параметров `customFilterStart` и `customFilterEnd` между экранами через `localStorage` и `window.appData`.
- Оптимизирована функция `applyFilters` для корректной работы с произвольными диапазонами дат.

## [2.1.0] - 2026-11-02
### 🎉 Новые возможности
- **Умный баннер для новичков**: приложение автоматически определяет вход в середине периода (после дня получения дохода) и показывает подсказку с инструкцией.
- **Пошаговая инструкция**: модальное окно с 4 шагами настройки для новых пользователей (универсальный текст для любого типа дохода: пенсия, зарплата, стипендия).
- **Счёт "Наличные"**: выделен в отдельную логику, доступен для доходов и расходов.
- **Накопительные счета**: исключены из формы расхода (только через трансфер), удалена категория "Накопления" из расходов.
- **Защита от перерасхода**: Приложение автоматически проверяет баланс всех счетов (Сбербанк, ВТБ, Тинькофф, Наличные) и блокирует расход, если средств недостаточно.

### 🐛 Исправления
- Исправлено отображение начального остатка в настройках (убраны артефакты floating point: `25656.010000000002` → `25656.01`).
- Исправлено ложное срабатывание "Недостаточно средств" для банковских счетов.
- Исправлено сравнение дат при расчёте баланса (корректная работа с объектами `Date`).
- Устранён артефакт `) -->` в HTML (конфликт комментария с live-server).

### 📱 Улучшения UX/UI
- Адаптивная вёрстка статистики: проценты больше не вылезают за границу экрана на мобильных устройствах.
- Добавлена кнопка "Как настроить?" в баннере середины периода.
- Универсальный текст вместо узкого "пенсия" → "регулярный ежемесячный доход".
- Исправлен перенос символа «₽» в суммах на экране сверки с банком (добавлен `white-space: nowrap`).

### 🔧 Технические изменения
- Динамический расчёт баланса счёта: `initialBalance` + транзакции текущего периода.
- Фильтрация транзакций по `currentPeriodStart` для корректного расчёта.
- Поле "Начальный остаток" в настройках сделано только для чтения (рассчитывается автоматически).

## [2.1.0] - 2026-10-24

### 🐛 Исправления
- **Критическое исправление логики смены периода:** Кнопка "Изменить" дату поступления пенсии теперь автоматически и корректно пересчитывает начальные балансы всех счетов при переходе в новый период.
- Функция расчёта баланса теперь честно учитывает все транзакции (включая операции самого дня смены периода до 23:59:59), что предотвращает потерю данных или появление отрицательных балансов при ручном изменении даты.
- Устранена рассинхронизация между глобальным начальным остатком и балансами отдельных счетов.

### ✅ Тестирование
- Логика протестирована на локальном сервере и на реальном устройстве (смартфон).
- Балансы счетов успешно сверены с реальными данными банковских приложений.
