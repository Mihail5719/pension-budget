# Наблюдения тестового периода v1.4

Период: 20.09.2026 — 04.10.2026 (две недели реальной эксплуатации)
Цель: собрать материал для проектирования v2.0 (PWA, рефакторинг, руководство)

---

## 20.09.2026

### Наблюдение 1: Расхождение баз при правках на одном устройстве
- **Ситуация:** отредактировал категорию записи (880 ₽, 30.08) только
  на смартфоне. Десктоп не узнал — в статистике категории разошлись
  (Продукты vs Другое).
- **Причина:** три независимых localStorage (верстак, стенд, смартфон),
  ручная синхронизация через экспорт/импорт легко пропускается.
- **Временное правило:** смартфон = мастер-устройство. Десктоп = просмотр.
  После пачки правок — экспорт→Telegram→импорт в тот же день.
- **Идея для v2.0:** индикатор синхронизации в Настройках:
  счётчик записей + дата последнего экспорта. Расхождение видно сразу,
  а не через статистику.

### Наблюдение 2: Надпись "Нет расходов за этот период" на мобильном
- **Ситуация:** после очистки периода надпись на смартфоне выходила
  за правую границу карточки.
- **Причина:** текст рисовался на canvas — на плотных экранах
  внутренняя сетка пикселей рассинхронизировалась с размером элемента.
- **Исправлено:** надпись перенесена в DOM (HTML-элемент), центрируется
  через CSS-отступы. Коммит в v1.4-test.

### Наблюдение 3: Кнопка сброса/изменения периода слишком доступна
- **Ситуация:** на узком экране смартфона легко нажать случайно.
- **Идея для v2.0:** добавить подтверждение перед сбросом периода
  ("Вы уверены? История текущего периода сохранится в истории, но
  статистика пересчитается").

### Наблюдение 4: Три независимых "склада" данных
- **Ситуация:** верстак (127.0.0.1), стенд (github.io на десктопе) и
  смартфон — три разные базы в одном проекте. Глазом не отличить,
  нужна сверка.
- **Инструмент диагностики:** экспорт с каждого склада + сравнение
  через VS Code Compare (ПКМ → Select for Compare). Различия видны
  сразу, без поиска глазами.
- **Идея для v2.0:** единая база (например, через Backend/API) или
  хотя бы явный индикатор "на этом устройстве N записей, последний
  импорт M дней назад".

  ### Наблюдение 5: Путь первого пользователя — статистика не отрисовывалась
- **Ситуация:** новый пользователь видел на статистике пустой холст
  без надписи "Нет расходов за этот период".
- **Причина:** renderAll вызывал renderTodayScreen, renderTransactionList
  и renderSettings, но пропускал renderStatsChart. Статистика
  отрисовывалась только при явном переключении на её экран в обжитой базе.
- **Исправлено:** renderStatsChart добавлена в renderAll — статистика
  теперь всегда актуальна, независимо от истории пользователя.
- **Урок:** тестировать "пустой первый запуск" не менее важно, чем
  работу на своих данных.

  ### Наблюдение 6: Третий уровень детализации — конкретный товар/заметка
- **Ситуация:** покупая колбасу или сосиски, вынужден записывать
  их в подкатегорию "Мясо и рыба" — это не точно, колбаса не мясо.
- **Хочу:** дополнительное текстовое поле к транзакции
  ("заметка" / "статья" / "товар"), куда можно вписать конкретное
  название покупки.
- **Зачем:** видеть в статистике не просто "Мясо и рыба = 1250₽",
  а "Свинина 650₽, сосиски 220₽, колбаса 380₽" — это даёт
  аналитическую силу для пересмотра привычек.
- **Идея реализации (отложить на v2.0+):**
  - Поле `note` (строка) в транзакции, опциональное
  - В списке истории — мелким серым под суммой
  - В детализации — третий круг или список "топ заметок"
  - Возможно: теги вместо свободного текста (но сложнее)
- **Сложность:** средне-высокая (требует миграции данных,
  новых UI-элементов, пересчёта статистики). Кандидат в v2.0+.

  ### Наблюдение 7: Долги и переводы между своими счетами некуда деть
- **Ситуация:** возврат долга (4 платежа, 8 089,41 ₽) записан в расход
  "Другое → Прочее". Категория раздута до 22% всех расходов, круг
  статистики показывает долги вместо жизни, дневной лимит искажён.
  Переводы между своими счетами (банк ↔ Сбер) тоже некуда деть.
- **Хочу:** отдельные ТИПЫ операций, не являющиеся доходом/расходом:
  * Долги: мне дали в долг / я дал в долг / я вернул долг
  * Переводы: между моими счетами (в обе стороны)
- **Зачем:** долги и переводы — движение денег, а не трата на жизнь.
  Они должны влиять на баланс, но НЕ на статистику расходов
  и НЕ на дневной лимит.
- **Идея реализации (v2.0+):** расширить поле type:
  'expense' | 'income' | 'debt_in' | 'debt_out' | 'debt_repay' | 'transfer';
  исключить новые типы из renderStatsChart и расчёта dailyLimit,
  но учесть в балансе; в истории показывать отдельным значком.
- **Сложность:** высокая (модель данных, баланс, статистика, история,
  экспорт/импорт, миграция старых записей). Флагманская задача v2.0+.

  ### Идея 5: Drill-down — круг подкатегорий по клику на категорию
- **Хочу:** клик по сектору круга или карточке категории →
  выезжает круговая диаграмма подкатегорий этой категории.
- **Зачем:** два уровня детализации без загромождения экрана:
  сначала "куда вообще", потом "из чего внутри".
- **Технически:** данные уже сгруппированы (renderSubcategoryBreakdown),
  Chart.js умеет клик по сектору (onClick), выезжание = CSS-анимация.
- **Сложность:** средняя. Кандидат №1 на v2.0.

### Идея 6: Свайп-переключение экранов на смартфоне
- **Хочу:** свайп справа налево / слева направо листает экраны
  (Сегодня → История → Статистика → Настройки).
- **Зачем:** родной мобильный жест, большой палец не тянется к кнопкам.
- **Подводный камень:** отличать горизонтальный свайп от вертикальной
  прокрутки списков, не сломать прокрутку истории.
- **Сложность:** средне-высокая. Кандидат №2 на v2.0, после drill-down.

### Рабочее правило (принято 20.09.2026):
> Правки категорий и записей делаем ТОЛЬКО на смартфоне (мастер).
> Десктоп — просмотр + импорт после пачки правок.
> Верстак (127.0.0.1) — лаборатория для тестов, не синхронизируем.
